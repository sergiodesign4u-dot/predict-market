Navigation

Navigation design

User-model rationale

Navigation is derived from the user's job sequence, not from a competitor tab bar. The primary path is: follow an event (find what is happening in the world) - place a stake (confirm your opinion with real money) - watch the position move (return to track odds) - return for the resolution (see what happened and how you did) - build reputation (show you were right). Each bottom-nav slot maps directly to one phase of this loop. Service-layer concerns - money, history, other users, help - live at the second level or are invoked in context, never a scarce top-level slot.

Alternative considered and set aside

A 3-slot version placing Notifications as a header bell icon was considered and set aside. The unread badge must be permanently visible in the thumb zone to drive hot/warm return (FJ1, FJ5, EJ3 depend on it; aarrr.md D1-D3). A header bell is easy to miss on mobile. The badge in the bottom bar earns its slot.

Depth risks

No depth risks for the primary persona's confirmed jobs at this navigation structure. All primary-persona paths reach their destination in 3 taps or fewer, with contextual shortcuts where the job depends on speed (G1, re-deposit).

Non-trivial checkmark rationale

FJ2 + EF
Event Feed shows each event's question and probability %, so it opens "why this probability"; the full context (the "why this price" block) moved to Event Detail in the wireframe build pass, which closes FJ2. The feed enters the job, Event Detail completes it.
EJ2 + EF
First impression of the product (benchmark-trust C5: 5/5 Bet365) is Event Feed without registration. Cognitive clarity on the first screen = first layer of EJ2.
FJ3 + BS
Bet Screen has $5 default pre-fill, quick-select buttons, and fee display - this is "bet without learning unfamiliar technology" at the confirm step.
EJ1 + ED
Knowledge validation: user sees the probability and compares it to their own forecast - "market thinks 67%, I know better." The sense of edge emerges here.
EJ1 + AB
Tracking price movement of their position (position monitoring) - intermediate confirmation that "I was right, price is moving my way."
FJ3 + WA
Wallet "Deposit again" button - re-entry into the top-up flow without a crypto barrier, for returning users.

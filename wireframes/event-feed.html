annotations: zone to job / finding
  1. 3-slot primary nav, no duplicate Profile -> Desktop layer D-desktop-1: Events, My Bets, Notifications in the bar; the avatar carries Profile (dedupe).
  2. Avatar dropdown -> populated from our IA only (My Profile, Wallet / Deposit, How It Works, Logout); shown open so the contents are visible. How It Works lives here and in the footer, not in the header bar.
  3. Balance plus Deposit in the cluster -> G4 holds: money is a utility in the cluster, not a primary destination, so it does not signal a trading terminal.
  4. Notifications badged in the nav -> retention anchor (FJ1, FJ5, EJ3; aarrr D1-D3). First-class, not demoted to a bell.
  5. YES/NO trigger-entry on the card -> routes to Event Detail with the side (and for multi-outcome the option) pre-selected. It does not place a bet and does not bypass Event Detail, so FJ2 (context before the bet) is preserved (IA/flows.md trigger-entry edge).
  6. Compact % (binary and per-option) -> Addition A: meaning shown as a number, but it does not dominate the card.
  7. No category badge, no context snippet -> the FJ2 context is now concentrated on Event Detail; the card is clean. Category lives in the filter.
  8. Multi-outcome layout -> a normal Event.Type layout (options plus % plus compact YES/NO), NOT the rejected trading-board view.
  9. Bookmark plus Saved view -> convenience and retention (FJ1 return). The proactive saved-event alert is a hypothesis, not a confirmed Notification type. Saved is a view under Events, not a new screen.
  10. In-heading controls, Trending default -> controls sit on the "Live events" row; Trending is the default sorted view, not a neutral "All".
  11. Footer (risk + responsible play) -> EJ2/FJ4 trust, a harm-aware line. Regulatory and licensing text is a placeholder, never invented.
  12. Sample-content honesty -> Addition B: every event here is illustrative sample data, never a real market or a verified fact.

responsive behavior (verify by resizing)

Mobile base: 1-column feed, bottom nav (4 slots). At >=640px: 3-slot top nav replaces the bottom nav, 2-column feed. At >=960px: 3-column feed. At >=1280px: 4-column feed. Cards stay legible at every width.

logged-out header delta (auth-state axis, header-level only)
Predict Market

Only the right cluster changes: "Sign in" replaces the Portfolio / Cash balance, Favorites, Notifications, and the avatar (on mobile, the Portfolio bottom slot becomes a "Sign in" entry too). The logo (Events home), the second-level category nav, the feed body, and all cards are identical and browsable. No separate logged-out page is built (Auth-state axis); the real auth branch is at the gate (Bet Screen Confirm -> Sign In -> Deposit).

annotations: zone to job / finding
  1. Logo = Events / home -> primary entry; clicking the brand returns to the Event Feed. Event-first identity, consistent with G4.
  2. Hamburger (left) -> reserved for future scaling; no primary items at MVP (Events is the logo, My Bets is in the avatar menu).
  3. Balance: Portfolio / Cash swap (desktop cluster only) -> one figure at a time, swap icon toggles Portfolio (= Cash + In-play, shown $142) and Cash (= available, $42). Not two figures like competitors. On mobile the balance is removed from the header (no room at 360px) and surfaced in the Portfolio bottom slot instead. G4 still holds on desktop: money is a utility in the cluster, Deposit lives in the avatar menu.
  4. Favorites (Saved view) -> opens the Saved filter over the feed. On mobile it is a bottom-bar slot (thumb reach for active filtering to your watchlist); on desktop it is a heart icon in the header. Saved is a view, not a new screen.
  5. Notifications (header bell on both breakpoints) -> bell icon + permanent badge in the header at all widths. Swapped with Favorites (the bell left the bottom bar; Favorites took the slot). The badge is visible whether at top or bottom, so the retention anchor (FJ1, FJ5, EJ3; aarrr D1-D3) is preserved; the thumb slot goes to a more actively-navigated control (Favorites). Overrides the locked bottom-slot-for-Notifications decision.
  6. Portfolio bottom slot (mobile, combined account hub) -> replaces the Profile slot; shows the portfolio sum ($142) instead of an icon, label "Portfolio" (Kalshi-style). Opens My Profile extended with a portfolio summary on top (Portfolio / Cash, Deposit) above the track record. A deliberate, documented partial override of G4: the slot is the account / identity hub with a balance, not a bare trading wallet. Profile is no longer a separate bottom slot; reputation stays reachable here and via the desktop avatar. My Bets is untouched (positions / history), no duplication.
  7. Avatar dropdown -> collapsed by default, opens on click (keeps the header short). Items: My Profile, My Bets, Wallet / Deposit, How It Works, Logout. My Bets now lives here on desktop; on mobile it stays a bottom-nav slot.
  8. Second-level category nav -> Trending (default), Politics, Crypto, Culture, General as a sub-nav band under the header. Categories are navigation (second level), separated from feed controls.
  9. Feed heading echoes the active category -> the heading is the selected second-level category (here "Trending"), not a generic "Live events". It updates when you pick another category.
  10. Filter row (Kalshi-style dropdowns on the heading row) -> three controls, each label showing the current value: Sort (Trending, Volatile, New, Closing soon, Volume, 50-50 plus a Reverse toggle), Frequency (All, One-time, Hourly, Daily, Weekly, Monthly) and Category. Feed controls, not navigation.
  11. Frequency -> recurring markets (NEW concept) -> introduces event cadence (one-time vs hourly/daily/weekly/monthly recurring markets). New Event attribute, added to IA/sitemap.md Event entity; resolution mechanics for recurring markets to be detailed later.
  12. Category dropdown syncs with the chips -> the heading-row Category control is the full category list (scales as categories grow) and stays in sync with the second-level chip nav and the heading; both update the active category.
  13. Card entry = the question title (no Open button) -> the large "Open event detail" button was removed from every card; the card title is the link to Event Detail (neutral entry). Cards stay compact and the list scans faster.
  14. YES/NO trigger-entry on the card -> routes to Event Detail with the side (and for multi-outcome the option) pre-selected. It does not place a bet and does not bypass Event Detail, so FJ2 is preserved (IA/flows.md trigger-entry edge).
  15. Compact %, no badge, no snippet -> Addition A: the number is shown but does not dominate; FJ2 context is concentrated on Event Detail.
  16. Multi-outcome layout -> max 2 visible positions -> the feed card shows at most the two leading positions (the options with the highest probability / most stake right now) and nothing else, no "+N more" line. The full option list is seen after the user opens the event (via the question link). Dropping the extra line keeps multi-outcome cards close to binary-card height, so the meta row lines up across the grid instead of leaving empty space. NOT the rejected trading-board view.
  17. Bookmark icon in the card meta row -> moved into the meta row as a small element (no card footer). Saves / follows the event, feeds the Saved view (retention, FJ1 return). The proactive saved-event alert is a hypothesis, not a confirmed Notification type.
  18. Footer (multi-column product footer) -> EJ2/FJ4 trust. Structured from a prediction-market competitor scan (Polymarket, Kalshi, Manifold, Limitless): a brand block (logo, tagline, social icons, language), a Markets column (by category + by topic), Product, Support and Company columns, and a bottom legal strip. X / Twitter and Discord are the mandatory social pair; Instagram, TikTok and Telegram extend reach. Regulatory and licensing text is a placeholder, never invented. Anything outside MVP carries a dashed TBD / post-MVP / dynamic tag, so the footer doubles as a roadmap. Skipped (no competitor uses them in the footer, not MVP): app-store badges and a newsletter.
  19. Sample-content honesty -> Addition B: all events are illustrative sample data, never a real market or a verified fact.

desktop header model (revised)

Lean header. Left: hamburger (reserved) + logo (= Events home). Desktop right cluster: Portfolio / Cash swap, Favorites (heart), Notifications (bell + badge), avatar dropdown (My Profile, My Bets, Wallet / Deposit, How It Works, Logout). Second-level category nav under the header. Mobile: header drops the balance; right side keeps the Notifications bell (badge) + avatar. Bottom nav (icons): Events, My Bets, Favorites, Portfolio (balance + account hub, replaces Profile).

responsive behavior (verify by resizing)

Mobile base: 1-column feed, bottom nav (4 slots), lean header. At >=640px: bottom nav hidden, 2-column feed. At >=960px: 3 columns. At >=1280px: 4 columns. Header and category nav are present at every width.

documented variant (not built here)

Return-visit denser layout: on return visits the feed is denser per IA/sitemap.md Event Feed. A documented variant, not a separate page in this step (P3-4 naming deferred).

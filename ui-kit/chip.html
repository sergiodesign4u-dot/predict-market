How this is read

The component in the markup it ships with, quoted from the frozen kit, inside the product's own wrapper and painted by components/index.css alone. Each frame is a page of its own, so the width under the title is a real viewport and the media queries answer to it. One row per CONTROL, in one column, and a scope is present only where the scope is what the row is about: twelve of the sixteen combinations the product wears were measured against the same markup with no scope above them and came out identical over thirteen properties, so a plate around those would be showing the reader a dialog to prove something about a button. The numbers for every row are in the axis table further down, written once.

What it is

A label a person picks between, when the choice is small, immediate and does not leave the screen. Four time ranges under a chart, three sort orders over a comment thread. It carries a value rather than doing a thing, so what it looks like afterwards matters more than what it looks like while it is pressed.

Anatomy

Which part is which, in the product's own words. Every class named here is one this file styles, and the build fails if it is not.

  • .chip - the control: no edge, no ground, --text-muted ink, a 10px corner, 12px semibold, 4 by 12 of padding. It is quiet on purpose, because a rail of five chips with five grounds is five buttons.
  • .chip.sel - the chosen one. A brass TINT, brass ink, bold, and the state is a class rather than a pseudo because the selection survives the pointer leaving. .sel is the shared modifier declared in ui-kit/_levels.py, so the same word means the same thing on every chip in the product.

How this is read

The frames above are the rendering; this is the reading of them. Every number was taken in a browser with a REAL pointer, a real Tab and the mouse button really held down (ui-kit/_verify/states.cjs), because a hover value is the cascade resolved and cannot be read out of a declaration. Nothing here is a state faked with a stand class. Two elements that measure the same in all four states in both themes are one answer, however many screens carry them, and that grouping is computed rather than chosen. The ring is the tenth value and it joined on 2026-08-05: outline is drawn outside the border box, so it is not the face in the strict sense, and for a stage this page said so and reported that focus moves nothing on 93 groups, which is the one state whose whole content it was not reading. The numbers go stale the moment a rule changes, so each block records the files it was measured from and python3 ui-kit/_states.py fails when their bytes move.

When to use

The judgement a generator cannot read out of css, and the reason ui-kit/authored/chip.md exists.

For a set of two to five values a person switches between on the spot, inside a container that gives them their ground: a trough, a rail, a segment. Both of today's placements are exactly that.

Not as a way of navigating. A chip that takes you somewhere is a link wearing a control's clothes, and the product already has a tab for a switch that changes a panel and a category chip for a rail that changes a page.

Not for a set that has to be scrolled. Five is a rail, twelve is a menu that has forgotten it has one.

The rule, and the anti-rule

One sentence to follow and one mistake worth naming. An anti-rule has to name the component that should have been used instead, or it is a complaint rather than an address, and the build checks that it does.

Do

A selected chip is a tint, never a fill. A solid brass ground is the primary action's own face, and a rail of chips is not asking anybody to commit to anything. DESIGN.md decides it twice, under Chips and under the One-Accent Rule, and components/quick.css records what it cost the one time a chip took the fill: a lit brass $20 sitting directly above a lit brass Add funds.

The container gives the ground, not the chip. Every rule in components/chip.css is scoped to .app-case, and none of them paints a ground at rest. That is what lets one control stand in a --bg-well trough and on a bare section without either looking wrong, and it is why the stand shows both rails rather than the chip on the canvas.

Never

Never draw it again in the file of whatever holds it. That is exactly how it came to exist twice: comments.css owned the sort segment because the segment stands in the comment controls, tabs.css owned the chart range because the range stands under the chart, and each file was right about its container and wrong about the control. If a third rail needs this chip, it takes .chip; if the third rail needs a chip that is genuinely different, the difference goes here as a modifier, next to .sel.

Never confuse it with the raised chip. .load-more and .feed-inner .cat-nav button are the other one: --bg-chip ground, a bevel edge, 14px semibold, and they are four declarations apart from each other rather than zero. That family is not merged yet and this file does not pretend it is.

Seen: ui-kit/docs/backlog.md S41, and ui-kit/docs/defects.md, which records the measurement that ended the duplicate.

So the authored half names its sources before it says anything, and the build fails when one of them does not exist.

  • ui-kit/docs/backlog.md S41, which owns the chip family and says this merge needs the shape the buttons got rather than a file move.
  • DESIGN.md, twice: "active is a brass tint" under Chips, and the One-Accent Rule. Both decide the selected state below.

/* components/chip.css
   Component: chip. Classes: .chip, .chip-amount, .chip-quiet, .chip-rail.

   Reads:
   Stand:  ui-kit/chip.html
   Stands on: 105 ui-visual screens (404.html, 500.html, active-bets-empty-new.html, active-bets-empty-resolved.html, active-bets-error.html, ...)
   Colour goes through a role, geometry straight from a primitive. No em dash. */

/* ============================================================================
   TWO FILES WERE DRAWING ONE CONTROL, AND NOT NEARLY: IDENTICALLY. On
   2026-08-05 `components/comments.css` styled `.cmt-controls .seg button` and
   `components/tabs.css` styled `.ed-range button`, and the four painted rules
   were the same declaration block twice, byte for byte, down to the order of
   the properties:

       border:0; background:transparent; color:var(--text-muted);
       border-radius:var(--radius-10); padding:var(--space-4) var(--space-12);
       font-family:var(--font-body); font-weight:var(--weight-semibold);
       font-size:var(--text-12); cursor:pointer;
       transition:background var(--dur-quick) ease, color var(--dur-quick) ease

   plus the same hover, the same press and the same `.sel`. The browser agreed
   before the files were read: `ui-kit/_states/index.json` had already measured
   both at `rgba(0,0,0,0)` ground, `rgb(164,157,143)` edge and ink, 10px corner,
   and both selected states at `rgba(199,162,78,.16)` on `rgb(215,172,83)`.

   NEITHER FILE COULD TAKE THE OTHER. A file that styles another component's
   classes is what S11 forbids, and `.seg` belongs to the comment controls while
   `.ed-range` belongs to the chart head. So the control gets the shape the
   buttons got in `447d1fb`: ONE MARKER CLASS on the element, and the markup of
   both trees moved in the same change as the stylesheet. 63 buttons per tree,
   9 screens each family.

   WHAT DID NOT COME WITH IT. `.cmt-controls .seg button{border-right:...}` and
   its `:last-child` are the GREY layer: unscoped, outranked by `.app-case` in
   the paint, and drawing the divided segment the wireframes still show. They
   stay in `comments.css`, with the container, because that is what they are
   about.

   AND THIS IS ONE OF FOUR, NOT THE FOUR. `.load-more` and
   `.feed-inner .cat-nav button` are the OTHER chip, a raised one on `--bg-chip`
   with a bevel edge at 14px, and they are four declarations apart rather than
   zero (padding 24 against 20, min-height 44 against 0, a letter-spacing, an
   inset groove). `.quick button` is a third face and the pill `.cat-nav button`
   outside `.feed-inner` a fourth. This file is where they come when each is
   measured and moved on its own evidence, and backlog S41 owns the rest.
   ============================================================================ */

/* NO GREY LAYER HERE, AND THAT IS A DECISION THIS PASS PAID FOR. The draft of
   this file opened with `.chip{cursor:pointer}`, copied from the note
   components/quick.css carries about keeping an unscoped first layer. It would
   have applied to nothing: the only documents that carry `.chip` and load this
   stylesheet are the painted screens, the specimen and the frozen kit, and all
   three put it inside `.app-case`. The nine grey screens that carry it link
   nothing from components/ at all.
   The reason for leaving it out is written in components/comments.css, where
   two rules of exactly that kind had been sitting since the file was cut. They
   never reached the wireframes either, and the day the chip's painted rule
   dropped from (0,3,1) to (0,2,0) they stopped losing and started painting: 45
   screens and 180 elements, found by snap.cjs and by nothing else. */
.app-case .chip-rail{border:0;background:transparent;color:var(--text-muted);border-radius:var(--radius-10);padding:var(--space-4) var(--space-12);font-family:var(--font-body);font-weight:var(--weight-semibold);font-size:var(--text-12);cursor:pointer;transition:background var(--dur-quick) ease,color var(--dur-quick) ease}
.app-case .chip-rail:hover{color:var(--text-primary)}
.app-case .chip-rail:active{background:var(--bg-pressed)}
/* A SELECTED CHIP IS A TINT, NOT A FILL, which is the rule DESIGN.md states
   under Chips and the One-Accent Rule states again: brass carries identity, the
   active state and primary CTAs only. `.sel` is the shared modifier
   `ui-kit/_levels.py` declares, so the state is a class rather than a pseudo,
   because the selection survives the pointer leaving. */
/* The one selected chip, S35, 2026-08-06: the same tint, the same ink and the same halo the 815
   category chips wear. No edge, because this chip has none at rest and the recipe colours what
   a chip already has rather than adding a part - giving it a 1px band here would move 63 boxes
   by 2px to say something the ground is already saying. */

/* ================================ the atom gets its faces, 2026-08-06 (S35) ==
   THIS FILE HELD ONE FACE AND THE ATOM HAS FOUR. `ui-kit/docs/atoms.md` counts
   1,358 placements of a control that carries a value and is picked between, in
   four files, and S35 has just settled the one thing they all have to agree on:
   what CHOSEN looks like. That agreement is the reason to move them, and it is
   written once below instead of four times.

   THE FACES ARE ANSWERS TO A SURFACE, which is what every atom on this map has
   turned out to be:

     rail      transparent, no edge, a 10 corner - a segmented control on a plate
     quiet     transparent on a transparent 1px band, a pill - a scrolling strip
               in the header, where a ground would make a row of eight read as
               eight buttons
     amount    --bg-control on a hairline, a 10 corner - a form control in a
               sheet, where a chip is one of the things you fill in

   THE 1px TRANSPARENT BAND ON `quiet` IS NOT DECORATION and is the same trick
   components/button.css uses: the box is the SIZE's answer, so a chip does not
   grow by 2px at the moment it is chosen and given a brass edge.

   AND SELECTED IS ONE DECLARATION NOW, for every face and for both ways the
   product says it. A rail chip and an amount carry `.sel`; a category chip is
   inside `li[aria-current="page"]`, which is the correct thing for navigation
   and is not going to be replaced by a class. Two selectors, one rule. */
.app-case .chip{cursor:pointer;font-family:var(--font-body)}
.app-case .chip-quiet{display:inline-flex;align-items:center;min-height:0;background:transparent;border:1px solid transparent;border-radius:var(--radius-pill);color:var(--text-muted);font-weight:var(--weight-semibold);font-size:var(--text-13);padding:var(--space-8) var(--space-12)}
.app-case .chip-quiet:hover{color:var(--text-chip-hover);background:var(--tint-hover)}
.app-case .chip-amount{border:1px solid var(--border-hairline);border-radius:var(--radius-10);background:var(--bg-control);color:var(--text-primary);padding:var(--space-8) var(--space-8);font-size:var(--text-12)}
.app-case .chip-amount{transition:border-color var(--dur-quick) ease,background var(--dur-quick) ease,color var(--dur-quick) ease}
/* The amount answers a pointer, and both places it stands do now. The deposit
   sheet had this hover and the bet panel had none - the same face on the same
   control, one scope answering and the other silent, which is not a decision
   anybody took. `:not(.sel)` on both, because a chosen chip still answers
   nothing anywhere in this product and that is backlog S38. */
.app-case .chip-amount:hover:not(.sel){border-color:var(--border-brass-hover);color:var(--text-brass);background:var(--bg-control-hover)}
/* THE CHOSEN CHIP, ONE RULE FOR THE WHOLE FAMILY. --tint-brass-09 inside a
   --tint-brass-45 edge with --text-brass-chip, bold, and a halo that is a glow
   with negative spread rather than a lift, so there is nothing here to flatten
   on a press. The edge is written where the face HAS one: the rail chip is
   borderless at rest and stays borderless, because the recipe colours what a
   chip already has and adds no parts. */
.app-case .chip.sel,.app-case [aria-current="page"] .chip-quiet{background:var(--tint-brass-09);color:var(--text-brass-chip);font-weight:var(--weight-bold);box-shadow:0 0 10px -8px var(--glow-brass)}
.app-case .chip-amount.sel,.app-case [aria-current="page"] .chip-quiet{border-color:var(--tint-brass-45)}
/* The press, and each of these has to out-reach the chosen rule above it or it
   would be invisible on exactly the chip a person is standing on - which on a
   category strip is the one most likely to be tapped, because tapping it is how
   you get back to the top of it. Only the ground moves, so a chosen chip keeps
   its brass edge, its brass label and its halo. */
.app-case .chip-amount:active:not(.sel),.app-case [aria-current="page"] .chip-quiet:active,.app-case .chip-quiet:active{background:var(--bg-pressed)}

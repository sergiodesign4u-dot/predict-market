What it is

One setting a person turns on or off, answered on the spot. A 40x24 track, a 16px knob, and nothing between the two states but the knob's travel and the ground's colour.

It is a selector and not an action: ui-kit/_worn.py files it that way because pressing it does not DO a thing, it chooses one, and the reason the choice is visible afterwards is that the control stays lit.

Anatomy

Which part is which, in the product's own words. Every class named here is one this file styles, and the build fails if it is not.

  • .toggle - the track, and it is only ever written with role="switch" on it: 40x24, a pill, a graphite ground and a hairline edge. The state is the ARIA attribute and not a class, because a switch that is on has to say so to something other than a stylesheet, and its knob is a ::after at 16px, --text-muted when off and --control-knob when on, travelling by left rather than by transform so the 3px inset stays readable in the rule.

How this is read

The frames above are the rendering; this is the reading of them. Every number was taken in a browser with a REAL pointer, a real Tab and the mouse button really held down (ui-kit/_verify/states.cjs), because a hover value is the cascade resolved and cannot be read out of a declaration. Nothing here is a state faked with a stand class. Two elements that measure the same in all four states in both themes are one answer, however many screens carry them, and that grouping is computed rather than chosen. The ring is not among the nine values, because outline is drawn outside the box: a focus row that reports no movement is saying the face does not move, and the ring is on the live frame. The numbers go stale the moment a rule changes, so each block records the files it was measured from and python3 ui-kit/_states.py fails when their bytes move.

When to use

The judgement a generator cannot read out of css, and the reason ui-kit/authored/toggle.md exists.

For a setting that takes effect immediately and has exactly two states. Three placements today, all of them in a filter panel.

Never for a choice that needs confirming, and never as a way of asking a question: a switch whose label is a question ("Show closed events?") makes the OFF state read as "no", which is an answer a person did not give. Label the thing being switched, not the question about it.

For a choice between more than two values it is filters, the disclosure it stands inside: a list of labelled radios says what the options ARE, and a switch can only say yes or no to one of them. For a value a person picks off a rail rather than out of a menu it is quick or catnav, which are chips.

The rule, and the anti-rule

One sentence to follow and one mistake worth naming. An anti-rule has to name the component that should have been used instead, or it is a complaint rather than an address, and the build checks that it does.

Do

The track takes the brand brass when it is on, never green. Green and red are outcome semantics in this product, and a switch is not an outcome.

The size is a floor and not a preference: 40x24 under any pointer, because a switch is a target you hit rather than one you aim at.

Never

Never use it for a choice with more than two values. That is filters, the disclosure this control stands inside: a list of labelled radios says what the options ARE, where a switch can only say yes or no to one of them. A value picked off a rail rather than out of a menu is a chip, which is quick or catnav.

Never fake the knob with a hit area no measurement can see. The control's own box is 40x24, and an invisible pseudo stretched over a smaller track is a fix nobody in this repo can check, which is the reason S39 was fixed in the boxes rather than around them.

Never give the ON state --bg-pressed for its press. A switch that is on is a flat --color-action ground, so the quiet system press would read as "it turned itself off" and there is no gradient angle to reverse. It is the one control in the product that asked for a role of its own and got one, --color-action-pressed.

Seen: ui-kit/docs/backlog.md S39, where this control measured 40x22 under a coarse pointer, one of exactly three in the product below the WCAG 2.5.8 floor.

/* ============================================================================
   IT LEFT components/filters.css ON 2026-08-05, AND THE REASON IS THAT IT WAS
   NEVER PART OF IT. A switch and a sort menu are two control families, and the
   only thing they shared was a file name: the menu is a `<details>` holding a
   panel holding a list of labelled radios, which is a molecule, and this is one
   control with a knob, which is an atom. The stand was already saying so out
   loud by needing two specimens for one component.

   It is also what gate 39 was written to catch. `filters` had an EMPTY
   containment, so `_levels.py` called it an atom by arithmetic that had no
   information, and `ui-kit/docs/inventory.md` and the vitrine's side panel
   printed that as a decision somebody had taken. Nobody had. See
   `ui-kit/docs/defects.md` row 63 and backlog S41.

   TWO RULES DID NOT COME WITH IT, AND THEY ARE THE GREY-BOX FOSSIL. The old file
   opened with `.toggle{border:1px solid --border-hairline;font-size:--text-10;
   padding:--space-2 --space-8;cursor:pointer}` and a bold weight for the checked
   state. Every `.toggle` in both trees carries `role="switch"` - measured, zero
   exceptions - and the `[role=switch]` rule below re-declares the border, the
   padding and the cursor and sets `font-size:0`, so the fossil painted nothing
   and the bold weight was a weight on a 0px face. Deleted rather than carried.
   ============================================================================ */

/* THE TRACK IS 24 TALL AND IT WAS 22, WHICH IS TWO PIXELS UNDER THE FLOOR. Measured
   under a coarse pointer: 40x22, one of three controls in the product that fail
   WCAG 2.5.8. A switch is a target you hit, not a target you aim at, so the fix is
   the control's own box rather than an invisible pseudo stretched over it: a hit
   area no measurement in this repo can see is a fix nobody can check.
   AND THE TOKEN WAS WRONG BEFORE IT WAS SHORT. --icon-22 is the size of a MARK,
   and it was being asked for the height of a control; --size-24 is a size
   primitive and is what the other end of this declaration (--size-40) already
   reads. The knob is unchanged at 16 and re-centred: inner height 22, so 3 rather
   than 2. Three screens. */
.toggle[role=switch]{position:relative;width:var(--size-40);height:var(--size-24);border-radius:var(--radius-pill);background:var(--bg-control);border:1px solid var(--border-hairline);padding:0;font-size:0;flex:0 0 auto;cursor:pointer;transition:background var(--dur-quick)}
.toggle[role=switch]::after{content:'';position:absolute;top:3px;left:3px;width:var(--icon-16);height:var(--icon-16);border-radius:50%;background:var(--text-muted);transition:left var(--dur-quick) var(--ease-out),background var(--dur-quick)}
.toggle[role=switch][aria-checked=true]{background:var(--color-action);border-color:var(--color-action)}
.toggle[role=switch][aria-checked=true]::after{left:19px;background:var(--control-knob)}
/* The switch had no pointer state at all: its only feedback was the knob sliding, which is the
   RESULT of the click and not a sign the control is live. Both states exclude [aria-disabled=true]
   so the dead switch below cannot light up, and exclude [aria-checked=true] so neither swaps the
   brass ground out from under a switch that is ON. A checked switch is still pressless: see the
   note under the disabled rule. */
.toggle[role=switch]:not([aria-checked=true]):not([aria-disabled=true]):hover{background:var(--bg-control-hover)}
.toggle[role=switch]:not([aria-checked=true]):not([aria-disabled=true]):active{background:var(--bg-pressed)}
.toggle[role=switch][aria-disabled=true]{opacity:var(--opacity-disabled);cursor:not-allowed}
/* An ON switch is a flat --color-action ground, not the two-stop action gradient, so neither of the
   two press mechanisms fits it: --bg-pressed would read as "it turned itself off" and there is no
   gradient angle to reverse. It is the one control that asked for a role of its own, so it got one:
   --color-action-pressed, brass held down. Nothing else in the system needs it, because everything
   else brass is a gradient. */
.toggle[role=switch][aria-checked=true]:not([aria-disabled=true]):active{background:var(--color-action-pressed);border-color:var(--color-action-pressed)}

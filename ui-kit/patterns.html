Patterns

A pattern is an arrangement of components that repeated. It owns no colour, has no level, no specimen and no states, and it loads last in components/index.css because it has to be able to place what it holds.

Which of the two to reach for

This is the part of the page that decides something. The list below is the inventory; this is the rule, and it is written with this product's own cases because a rule stated in the abstract gets read as advice.

Take the pattern whole

When the screen is doing the job the arrangement is for, whatever it puts inside it. Favorites, My Bets, Wallet, Notifications and the four category feeds all browse a set, so all of them take the browse shell and then fill the column with fourteen different things. The arrangement is the answer; the content is the variable.

The test is whether you would describe the screen with the pattern's own sentence. "A rail beside a column" describes Wallet. If it does, take the whole thing, including the parts you do not think you need: the 900px switch and the :not(:has(.subcat)) fallback are what make it work on the screen that has no rail yet.

Assemble from components

When the arrangement would be a coincidence. The system pages (404, 500, maintenance) put one state block on a plate, and a state block on a plate is not a browse shell that happens to be empty: R8 says a system screen carries the frame and not the navigation, so reaching for the shell there would import a rail the screen is not allowed to have.

The second case is a count of one. .feed-hero stands on a single screen and .cc-banner on a single screen, so neither is a pattern and neither gets one: a composition used once is that screen's layout, and giving it a shared file makes the next person believe it repeats.

The condition for existing is three screens. Not three occurrences: three distinct files that carry the composition. A thing that repeats twelve times inside one screen is that screen's layout, and only a third screen proves the arrangement is not a local decision. Six compositions cleared it and two did not, and the two are named at the foot of this page rather than forgotten.

Candidates, waiting for a third screen

Compositions that repeat on exactly two screens. They are NOT patterns and nothing here is extracted, but they are on this page rather than in a commit message, because a candidate nobody can see is one the next round counts again from scratch.

.ptabs, .ptab-bar, .ptab-panel

The profile tab strip, six occurrences over two screens. The threshold is three SCREENS and not three occurrences, on purpose: a composition that repeats inside one screen is that screen's layout, and only a third screen proves the arrangement is not a local decision. It is also half of backlog item 16b, because tabs is an L1 switcher and an L3 tab panel in one file.

2 screens: my-profile, public-profile. Styled in components/tabs.css.

.opt-list

The full outcome list, on the two multi-outcome detail screens. Those two are one screen in two auth states rather than two arrangements, so the third is further away than the count suggests. It is already governed as a rule of use: R5 says the list never stands inside a card.

2 screens: event-detail-multi, event-detail-logged-out-multi. Styled in components/options.css.

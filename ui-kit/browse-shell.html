Browse shell

A sub-category rail beside a content column, stacked under 900px and side by side above it. It owns none of what it holds and paints none of it; it says where the two columns are.

Live

Cut out of event-feed-crypto-empty.html byte for byte, with the ancestor chain it has there, and painted by components/index.css alone. Every string is the shipped microcopy, because none of it was retyped. The rail is the point of this pattern and the base category pages do not show it: on those nine the markup ships <nav class="subcat" hidden> and a page script fills it. Twenty four screens carry it filled and visible, and every one of them is a STATE screen, so the scene is cut from one. Nothing here is set or unset by the generator: this is that screen's markup.

This is the only place the pattern exists outside the product. A component has a specimen as well as a stand; a pattern has neither, because step 3 took patterns out of gate 24's corpus deliberately: that gate compares what a component contains against what it contains on the screens, and a pattern contains whatever the screen puts in it. So this frame is not an illustration of the pattern, it is the test of it.

Anatomy

What each part is and whose it is. A part that belongs to a component links to that component's page, because the answer to "how does this look" is there and not here: this file decides placement and nothing else.

partwhose it iswhat it does here
.cat-layoutthis patternThe shell. Column at 360, row at 900 and up, and the gap changes with the direction because the distance between two columns is not the distance between two stacked blocks.
.subcatcatnavThe rail. Its own component: this pattern decides that it stands here, not what it looks like.
.cat-mainthis patternThe content column. flex:1;min-width:0, and the min-width is what stops a long word inside a card from pushing the rail off screen.

Everything inside, read from the markup: catnav (.subcat-head), filters (.filter-menu), state-block (.state-block), button (.state-btn). The class in brackets is what put each component in the list, through the same ownership map that computes the level and orders the cascade. A name here that surprises you is worth following: a class declared in the wrong file makes a pattern read as holding a component it has never seen.

Variants

.cat-layout:not(:has(.subcat))

No rail, so nothing to align to: the column takes the full height instead of hanging at the top of a row it is the only member of. Specificity 0,3,0 against 0,1,0, so this is decided by the selector and not by the order of the files.

When to use it

  • The screen browses a set: a category, a list of bets, a wallet ledger, a profile.
  • There is a second, narrower axis of navigation that belongs BESIDE the content rather than above it.
  • Fourteen different sets of content stand in the column across the 76 screens, which is the argument for a pattern rather than a component: the arrangement is stable and what it holds is not.

The rule

The rail goes first in the markup and the column second, at every width. The stacked order under 900px is the source order, so a rail written after the column would land under it on a phone and beside it on a desktop.

The anti-rule

Do not put the page's own surface on it. The two-stone plate under this shell is in components/base.css with the rest of the frame, because it is what the PAGE is made of and not what this arrangement is. A pattern that carries a background is a component with the label filed off.

The file

A pattern loads LAST in components/index.css, after every component, because it has to be able to place what it holds. It carries no colour at all, and gate 23 fails the build if one appears.

components/patterns/browse-shell.css
/* components/patterns/browse-shell.css
   Pattern: the browse shell. A sub-category rail beside a content column.

   Assembled from: catnav (the .subcat rail), feed, state-block, loadmore, tabs.
   It owns none of them and paints none of them; it says where they stand.
   Stands on: 76 ui-visual screens (event-feed x41, active-bets x9,
     notifications x5, public-profile x4, my-profile x3, wallet x3, favorites x3,
     event-detail x2, maintenance, how-it-works). Fourteen different sets of
     content across those 76, which is the argument for a pattern rather than a
     component: the arrangement is stable and what it holds is not.
   Moved here from: components/catnav.css, five rules, cut and not copied.
     .cat-layout and .cat-main were catnav's only because catnav was the first
     file that needed them; nothing in either rule is about a category.
   The SURFACE those two stand on did not come with them. The two-stone plate is
     the page's material, not this arrangement's, and it is in base.css with the
     rest of the frame.
   Colour goes through a role, geometry straight from a primitive. No em dash. */

.cat-layout{display:flex;flex-direction:column;gap:var(--space-12)}
.cat-main{flex:1;min-width:0}
@media(min-width:900px){
  .cat-layout{flex-direction:row;align-items:flex-start}
}
/* The gap belongs to the wide arrangement, and it is written apart from the
   direction above because at 900px the rail arrives and the distance between
   two columns is not the distance between two stacked blocks. */
@media(min-width:900px){
  .cat-layout{gap:var(--space-20)}
}
/* WITH NO RAIL THERE IS NOTHING TO ALIGN TO, so the column takes the full height
   instead of hanging at the top of a row it is the only member of. 0,3,0 against
   the 0,1,0 above, so specificity decides this and not the order of the files. */
.app-case .cat-layout:not(:has(.subcat)){align-items:stretch}

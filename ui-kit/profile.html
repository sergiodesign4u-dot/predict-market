One placement is the wrong size for an exception

Edit left this file on 2026-08-06 for the button family's small secondary. It is one placement in the whole product, and it wore a pill where the family wears 10, 11px where the family's small step is 12, and 8/16 where that step is 8/12.

Naming a face for a single element is what the atom rules forbid. So the element took the family's name instead, and three values moved by a step each.

And the file's own touch rule went with it, which is the better half of the story. This file had written target size follows the POINTER, not the viewport and then bound its own control to a 640px viewport query, so a touch tablet or a touch laptop got the 36px control. The rule was right and the implementation contradicted it. It is no longer written here at all: the family carries the floor for every one of its members, and this control is a member.

The rule

Identity first, record second. The row that says who you are comes before the numbers that say how you have done, and the numbers are position's.

A target follows the pointer, not the viewport. This file wrote that sentence and then contradicted it in its own query.

One placement never earns a face. It joins a family and moves by a step.

The anti-rule

Never bind a target to a width. A touch laptop is a coarse pointer at 1280 and got the 36px control.

Never write a rung as a colour function. Five hundredths off the ladder and invisible to everything that reads names.

Never report a gallery as missing without checking its tab. 0x0 at both widths, and the tab beside it was the reason.

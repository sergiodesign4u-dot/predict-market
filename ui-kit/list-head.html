List head

A title on one side, the controls that act on the list on the other, wrapping to two rows when there is no room for one.

Live

Cut out of event-feed.html byte for byte, with the ancestor chain it has there, and painted by components/index.css alone. Every string is the shipped microcopy, because none of it was retyped. The feed's own head, which is the widest case: a title, a live count and the full control row. Sixty nine other screens carry a thinner version of the same row.

This is the only place the pattern exists outside the product. A component has a specimen as well as a stand; a pattern has neither, because step 3 took patterns out of gate 24's corpus deliberately: that gate compares what a component contains against what it contains on the screens, and a pattern contains whatever the screen puts in it. So this frame is not an illustration of the pattern, it is the test of it.

Anatomy

What each part is and whose it is. A part that belongs to a component links to that component's page, because the answer to "how does this look" is there and not here: this file decides placement and nothing else.

partwhose it iswhat it does here
.feed-headthis patternThe row. flex-wrap with space-between, so the controls drop under the title instead of squeezing it.
.feed-controlsthis patternThe control side. A wrapping row of its own, because two controls that do not fit should sit under each other and not shrink.
.filter-menufiltersWhat usually stands in the control side.

Everything inside, read from the markup: filters (.filter-menu). The class in brackets is what put each component in the list, through the same ownership map that computes the level and orders the cascade. A name here that surprises you is worth following: a class declared in the wrong file makes a pattern read as holding a component it has never seen.

Variants

No variants. The pattern has one arrangement, and a screen that needs a different one needs a different pattern.

When to use it

  • A list needs a name and the list needs controls, and both belong to the list rather than to the page.
  • Twenty six of the seventy screens that carry the head have a title and nothing to sort, and the row is correct with the control side empty.

The rule

The sort control lives here and not in the category band. Categories are navigation; a sort is a control over THIS list, and putting it in the band makes it look like a place you can go.

The anti-rule

The heading's type is not here. A display face and its colour are what the block LOOKS like, so they stay in components/feed.css; this file is the row and nothing else.

Where it stands

The existence proof. A composition is a pattern here because it stands on three or more screens, so this list is not a footnote: it is the reason the file exists. Counted from the markup of all 104 painted screens, not from a list.

The file

A pattern loads LAST in components/index.css, after every component, because it has to be able to place what it holds. It carries no colour at all, and gate 23 fails the build if one appears.

components/patterns/list-head.css
/* components/patterns/list-head.css
   Pattern: the list head. A title on one side, the controls that act on the list
   on the other, wrapping to two rows when there is no room for one.

   Assembled from: a heading and filters. The heading's TYPE is not here: a
     display face and its colour are what the block looks like, so they stay in
     components/feed.css. This file is the row.
   Stands on: 70 ui-visual screens carry .feed-head (event-feed x41,
     active-bets x9, notifications x5, public-profile x4, my-profile x3,
     wallet x3, favorites x3, cookie-consent, toasts); 44 of them also carry
     .feed-controls, the rest have a title with nothing to sort.
   Moved here from: components/feed.css, four rules, cut and not copied.
   Colour goes through a role, geometry straight from a primitive. No em dash. */

.feed-head{display:flex;flex-wrap:wrap;align-items:center;gap:var(--space-8) var(--space-16);justify-content:space-between;margin-bottom:var(--space-8)}
.feed-head :is(h1,h2){margin:0}
.feed-controls{display:flex;flex-wrap:wrap;gap:var(--space-8)}
/* The painted layer takes the head's own bottom inset off, because on a plate
   the distance to the list is the plate's padding and not the head's margin.
   The border-bottom that used to be reset with it went to base.css with the
   plate: a rule that removes an edge is about the edge. */
.feed-head{padding-bottom:0}
.feed-head :is(h1,h2){margin-bottom:0}

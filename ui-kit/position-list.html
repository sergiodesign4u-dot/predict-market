Live

Cut out of active-bets.html byte for byte, with the ancestor chain it has there, and painted by components/index.css alone. Every string is the shipped microcopy, because none of it was retyped. My Bets, where the list is longest and the rows are the real thing rather than a loading stand-in.

This is the only place the pattern exists outside the product. A component has a specimen as well as a stand; a pattern has neither, because step 3 took patterns out of gate 24's corpus deliberately: that gate compares what a component contains against what it contains on the screens, and a pattern contains whatever the screen puts in it. So this frame is not an illustration of the pattern, it is the test of it.

Anatomy

What each part is and whose it is. A part that belongs to a component links to that component's page, because the answer to "how does this look" is there and not here: this file decides placement and nothing else.

Everything inside, read from the markup: position (.pos), profile (.pos-status). The class in brackets is what put each component in the list, through the same ownership map that computes the level and orders the cascade. A name here that surprises you is worth following: a class declared in the wrong file makes a pattern read as holding a component it has never seen.

Variants

No variants. The pattern has one arrangement, and a screen that needs a different one needs a different pattern.

When to use it

  • Rows of one kind stack and the distance between them is the only thing to decide.
  • The stack also holds the loading skeletons and the resolved record block, so what stacks is not always a position row.

The rule

The gap is the list's, never the row's. A row that carried its own bottom margin would double the distance the moment two lists sat one under the other, and the last row would push the plate's padding out by a step.

The anti-rule

Do not use it as a plate. A .pos carries its own stone, its own edge and its own ink; what this file decides is that the rows stack and how far apart, which is the one thing a row cannot know about itself.

Where it stands

The existence proof. A composition is a pattern here because it stands on three or more screens, so this list is not a footnote: it is the reason the file exists. Counted from the markup of all 104 painted screens, not from a list.

The file

A pattern loads LAST in components/index.css, after every component, because it has to be able to place what it holds. It carries no colour at all, and gate 23 fails the build if one appears.

components/patterns/position-list.css
/* components/patterns/position-list.css
   Pattern: the position list. A vertical stack of bet rows at one distance.

   Assembled from: position, and in two of its cases skeleton (the loading rows)

   Stands on: 13 ui-visual screens (active-bets x4, notifications x3,

components/base.css
/* components/base.css
   the page frame itself: reset, body type, the device shell and the shared utility classes.

   Reads: --bevel-faint, --bevel-hi, --bevel-lo, --bg-page, --bg-plate, --bg-plate-from, --bg-plate-to, --bg-slab, --bg-slab-from, --bg-slab-to, --edge-groove-dark, --edge-groove-light, --focus-ring, --scrim, --shadow-ink-45, --shadow-ink-60, --shadow-ink-72, --shadow-ink-85, --surface-grain, --surface-grain-coarse, --text-icon, --text-primary
   Stand:  ui-kit/base.html
   Colour goes through a role, geometry straight from a primitive. No em dash. */

/* THE FONTS ARE NOT IMPORTED HERE, AND THAT IS THE POINT. This file used to
   @import them, which meant the browser could not even discover the request
   until it had fetched and parsed index.css and then base.css: three hops for a
   render-blocking resource, while every page ALSO carried a <link> to the same
   URL in its head. One dependency, declared twice, on the slowest possible path.

   A system stylesheet should name the family it needs and let the document load
   it, which is also where the decision belongs: this is a third-party request
   that sends the visitor's IP to Google before any consent is given, and this
   product ships a cookie banner grounded in GDPR and ePrivacy. Self-hosting the
   three families is the production answer; until then the call is visible in the
   head of every page instead of buried three levels down in the CSS.

   Every head carries it: ui-visual/*.html in the markup, ui-kit through the four
   generators that share _theme_switch. --font-display, --font-body and
   --font-mono in tokens.css name what has to arrive. */

/* What is NOT here any more. base.css is the page frame: the reset, the body type, the device
   shell and the shared utilities. It was also carrying three components, because they arrived
   with the flat kit and nobody moved them: the market stats and the market-depth table (.ms-*
   and .md-*, now in market.css, which already owned .market-stats and .market-depth), the
   profile tab switch (#ptab-* in tabs.css) and the bet-sheet keyframe (betpanel.css). A file
   named for the frame is where a component goes to be invisible. */

*{box-sizing:border-box}
body{margin:0;line-height:var(--leading-base);color:var(--text-primary);font-family:var(--font-body-root);background:var(--bg-page)}
button,select,summary{font:inherit}
.ic{width:var(--icon-22);height:var(--icon-22);fill:none;stroke-width:1.6;stroke-linecap:round;stroke-linejoin:round;vertical-align:middle;display:block}
.ic-sm{width:var(--icon-12);height:var(--icon-12);fill:none;stroke-width:1.8;stroke-linecap:round;stroke-linejoin:round}
.ic,.ic-sm{stroke:var(--text-icon)}
svg.ic:has(use),svg.ic-sm:has(use){fill:currentColor;stroke:none}
/* FOCUS, DECLARED ONCE. Fourteen component files carried this exact rule and twenty-four did not,
   which is the shape reduced-motion had before step 7 gathered it here: a person navigating by
   keyboard is not asking each component separately. The default is below; a component now only
   speaks up when it needs something different (the theme switch wants an inset ring, a dialog link
   wants a radius, the bet amount field has to out-specify its own outline:none). */
:focus-visible{outline:var(--ring) solid var(--focus-ring);outline-offset:var(--ring)}

/* Marked important on purpose, and it has to stay that way. This is a
   visibility utility: the element it is on has its own display from its own
   component (.icon-btn and .bal-toggle both say inline-flex), and base.css is
   imported first, so without this the component would win and the desktop
   balance cluster would show up in the 380px header. In the flat kit the two
   sat in one file and the utility happened to come last. */
.desk-only{display:none!important}
@media (min-width: 640px){
  .desk-only{display:inline-flex!important}   /* pairs with the rule above */
}
/* The device is the slab the product sits on, and .app-case is the product
   itself: transparent, so the slab shows through. */
.device{width:100%;max-width:none;margin:0 auto;min-height:100vh;display:flex;flex-direction:column;position:relative;border:0;background-color:var(--bg-slab);background-image:var(--surface-grain-coarse),linear-gradient(180deg,var(--bg-slab-from),var(--bg-slab-to));background-blend-mode:overlay,normal}
.app-case{position:relative;background:transparent;border:0}
/* HIDDEN IS A STATE, NOT A STYLE, so nothing may out-declare it. The user agent
   hides with display:none from ITS sheet and any author declaration beats that
   whatever the specificity, so .card{display:flex} put twelve cards back on
   screen while the attribute said three. Raising the specificity here would only
   move the argument: the next component to declare its own display would win it
   again, and every component would have to remember. This is the case the word
   is for, an invariant of the frame rather than a preference between rules, and
   it is the one place in components/ that carries it.

   The check that first said the filter worked was counting :not([hidden])
   instead of asking the browser what it could see. A checker that reads the
   attribute does not read the page. */
[hidden]{display:none!important}
/* .app-case is transparent so the device slab shows through it. On the frozen kit
   the app-case IS the body, and a body with no background lets the canvas fall back
   to white. This is what the !important on body{background} used to be for. */
body.app-case{background:var(--bg-page)}
@media(min-width:860px){
  body:has(#rmSidebar){padding-left:var(--container-sidebar)}
}
/* The frozen kit still carries the wireframe's [TBD] and [placeholder] chips, and
   it must keep rendering the way it did, so the rule that hides them stays. The
   painted screens no longer have the markup at all (ui-visual/_strip_wireframe.py):
   an annotation about what is not built yet belongs in wireframes/, which owns it. */
.tbd,.placeholder-line{display:none}
/* THE PAGE A CATALOGUE DEMONSTRATES ON, which is a frame thing and not a
   component's. .tc-page is the section of ui-visual/toasts.html that stands in
   for whatever a toast would be covering: one screen, one class, one margin.
   It lived in toast.css, so the class map read the toast as OWNING the page it
   is demonstrated on, and therefore as containing the cookie banner that also
   stands there. Backlog item 16c, and the fix was always the address rather
   than the rule. */
.app-case .tc-page{margin-bottom:var(--space-16)}
.groove-sep{border-top:1px solid var(--edge-groove-dark);box-shadow:inset 0 1px 0 var(--edge-groove-light)}

/* ============================================================================
   THE PAGE FRAME, which arrived here in the patterns step and is not a pattern.

   .feed-inner stands on 104 screens of 104. A pattern is a CHOICE made on some
   screens and not others; a thing every screen is is the frame, and the frame is
   this file. Extracting it to patterns/ would have produced a file whose answer
   to "which screens use it" is "all of them", which is another way of saying the
   question does not apply.

   The two-stone plate came with it for the same reason, out of catnav.css and
   event-detail.css. It only ever applied under .feed-inner, so it was never the
   category strip's own skin or the detail column's: it is the surface a page
   stands on, and it was living in two component files because those were the two
   files that first needed a page to stand on. A pattern may carry no colour, so
   the arrangement went to patterns/ and the material came here, and the pair now
   sits at one address instead of two.
   ============================================================================ */
.feed-inner{max-width:var(--container-max);margin:0 auto;padding:var(--space-16) var(--space-20)}
/* THE INSET IS PADDING, NOT A MARGIN. Turning margin:var(--gutter) into
   margin:var(--gutter) auto to centre this band spent the horizontal gutter
   on the centring, so under 1400 the plate sat against the window edge. A
   container holds its inset at EVERY width; above the cap the auto margin
   centres and the padding keeps the same edge the header row has had all
   along. */
.app-case .feed .feed-inner{max-width:var(--container-max);margin:var(--gutter) auto;margin-top:var(--space-12);padding:0 var(--gutter);box-sizing:border-box;background:none;border:0;border-radius:0;box-shadow:none;display:flex;flex-direction:column;gap:var(--space-16)}
@media(max-width:640px){
  .app-case .feed .feed-inner{margin-top:var(--space-16);padding:0 var(--gutter)}
}

The arrangement is four declarations and one of them is written twice, once for an anchor child and once for a bare one, because the bar has each about as often. The second is a CHILD selector where the first is not: a button nested inside an anchor is not a flex item of this bar, so flex:1 on it would mean nothing.

The one place the step needed an exception

The cut had a rule: composition comes here, the page's plate goes to the frame, and the component keeps its paint. This bar is where the rule needed a third box.

The bar's own surface is a stone, a hairline along the top edge and two rounded top corners. That is not the page plate, so it does not follow the frame; it is not composition, so it does not come here. It is the paint of a component, and it stays in account.

The same split runs through .flat, and that is the sharpest version of it: the POSITION is in this file and the three declarations that take the surface away are in the component's. One class name, two files, and each file holds the half it is entitled to.

The rule

A pattern says where things stand and never what they look like. Four declarations, and not one of them is a colour, a face, a border or a surface.

Three screens, counted, and the count is written down. A pattern that clears the threshold by one screen says so, because the day a screen changes it is a candidate again.

The anti-rule

Never let a pattern declare a default nothing wears. Sticky is overridden by all three placements, and it reads as the intended behaviour to everyone who opens the file.

Never move a component's paint into a pattern to keep the cut tidy. The stone stayed in the component, and the exception is written where somebody will meet it.

What an organism is, and why this page had to change shape twice

An organism holds molecules, or it is a shell. A shell draws almost nothing itself and decides where everything else goes, which is why two of the entries below have fewer own rules than any atom on the vitrine and are still level 3. The level is declared in docs/inventory.md with a reason, because the arithmetic that computes it is blind to a component built out of its own class names.

The themes stack instead of sitting side by side. A molecule is a row and fits in half a column; a header cut to 430px is not a header. What a shell IS is the decision it takes about the full width, so measuring it at half width twice would be measuring something else and calling it the component.

And then two of them refused to be shown twice at all. That is the finding of this page and it is in the section under this one, because it is a property of the system rather than of the stand.

A specimen keeps the screen's href and takes the stand's prefix. One link on this shelf points at a screen, the feed shell's, and it reads ../ui-visual/event-feed.html: the name after the prefix is the product's, unchanged, and the prefix is a fact about which folder this document sits in rather than about the component.

Nine declarations in the system are keyed to a document-unique id

A class can appear a thousand times in a document. An id is unique by definition, so a rule written against one is not a rule about a component: it is a rule about one instance of it. Counted across all 51 stylesheets:

tabs.css writes #edtab-comments:checked ~ .ed-panel-comments and nine more of that shape, so the event tab set and the profile tab set each work exactly once per document. hero.css writes .hf-area{fill:url(#hfyes)}, so the hero's chart takes its gradient from whichever #hfyes the document happens to define first. The one in base.css is #rmSidebar and it is correct: there really is one panel per document.

Nothing is broken today, and that is the whole point. Measured over the 106 painted screens: 0 of the 13 ids appears more than once on any screen. One hero per feed, one tab set per detail page. The coupling has never fired because the product has never asked it to, and this page is the first thing that ever asked: a stand that shows a component twice in one document is the exact case an id-keyed rule cannot survive.

Which is why they are shown once, rather than shown wrong. Renaming the second copy's ids would leave the CSS pointing at the first copy; keeping them would make the daylight tab set steal the graphite one's checked state and the daylight hero paint with the graphite gradient. A stand that quietly shows a component painting with another copy's values is worse than a stand that says it cannot show it. Backlog 45.

What is left, and what this page could not answer

The one organism that was unmeasured is not any more. profile stands on none of the five anchor screens, so this shelf refused it a level rather than guessing one: the formula answers 1 for an atom and 1 for a file nobody has read, and the two are indistinguishable in the output. Walked on 2026-08-08 on the two screens that carry it, tabs cycled, containment read from the DOM: the identity row holds one button and the gallery holds three cards, so it holds an organism and it is level 3. Its page is profile.

Two are shown once, and that is the finding rather than a limitation of the stand. Until tabs.css and hero.css stop naming ids, neither component can be placed twice in one document by anybody, including a developer building a page with two tab sets on it. Backlog 45.

And the fourth rung is next. components/patterns/ holds six files whose criterion is repetition rather than nesting: a pattern is three screens or more, adds no styles of its own and carries no colour. Five of the six stand on the anchors and action-bar stands on none of the 41.

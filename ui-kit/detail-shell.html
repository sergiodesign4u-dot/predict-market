Detail shell

A content column beside a sticky side panel, stacked under 760px and side by side above it. The panel is the bet panel today and the pattern does not know that.

Live

Cut out of event-detail.html byte for byte, with the ancestor chain it has there, and painted by components/index.css alone. Every string is the shipped microcopy, because none of it was retyped. The canonical detail screen, in its ordinary state. The other ten are the same arrangement holding a different content set, which is exactly what the pattern claims.

This is the only place the pattern exists outside the product. A component has a specimen as well as a stand; a pattern has neither, because step 3 took patterns out of gate 24's corpus deliberately: that gate compares what a component contains against what it contains on the screens, and a pattern contains whatever the screen puts in it. So this frame is not an illustration of the pattern, it is the test of it.

Anatomy

What each part is and whose it is. A part that belongs to a component links to that component's page, because the answer to "how does this look" is there and not here: this file decides placement and nothing else.

partwhose it iswhat it does here
.ed-layoutthis patternThe shell. Column at 360, row at 760 and up.
.ed-mainthis patternThe content column, and the only one of the two this pattern sizes.
.bet-panelbetpanelThe side panel. Sticky at 120px from the top, and that belongs to the panel, not here.

Everything inside, read from the markup: card (.card), event-detail (.ed-head), oddsbar (.ed-oddsbar), chart (.ed-chart-head), feed (.grid-l), tabs (.ed-range), market (.market-box), comments (.cmt-controls), bets-table (.hold-cols), position (.pos-side), betpanel (.bet-panel), input (.field-label), button (.confirm-btn), dialog (.fine). The class in brackets is what put each component in the list, through the same ownership map that computes the level and orders the cascade. A name here that surprises you is worth following: a class declared in the wrong file makes a pattern read as holding a component it has never seen.

Variants

No variants. The pattern has one arrangement, and a screen that needs a different one needs a different pattern.

When to use it

  • One subject fills the screen and one persistent action must stay reachable while a person reads about it.
  • The action needs its own column on a desktop and its own dock at the foot of a phone.

The rule

The breakpoint is 760 and not 900, and it is the panel's own: at 760 the bet panel appears and the dock disappears, which is one swap in components/betpanel.css. Two arrangements changing at two different widths would leave a band where the page has both or neither.

The anti-rule

Do not reach into the column from here. .ed-main gets flex:1;min-width:0 and nothing else; its plate, its clip and its dropped right edge are in components/base.css.

Where it stands

The existence proof. A composition is a pattern here because it stands on three or more screens, so this list is not a footnote: it is the reason the file exists. Counted from the markup of all 105 painted screens, not from a list.

The file

A pattern loads LAST in components/index.css, after every component, because it has to be able to place what it holds. It carries no colour at all, and gate 23 fails the build if one appears.

components/patterns/detail-shell.css
/* components/patterns/detail-shell.css
   Pattern: the detail shell. A content column beside a sticky side panel.

   Assembled from: card, chart, market, tabs, betpanel. It owns none of them.
   Stands on: 11 ui-visual screens, every event-detail state (base, multi,
     resolved, loading, error, logged-out, and the five bet states).
   Moved here from: components/event-detail.css, three rules, cut and not copied.
   What did NOT come with them: the plate .ed-main stands on, and the border-right
     it drops. Those are the page's surface and they are in base.css. This file
     answers where the two columns are, and nothing about what they look like.
   Colour goes through a role, geometry straight from a primitive. No em dash. */

.app-case .ed-layout{display:flex;flex-direction:column;gap:var(--space-16);align-items:stretch}
.app-case .ed-main{flex:1;min-width:0}
@media(min-width:760px){
  .app-case .ed-layout{flex-direction:row;align-items:flex-start}
}

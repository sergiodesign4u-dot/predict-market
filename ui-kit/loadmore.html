Outcome pair, icon button and Load more

What it is

The end of the list, and the offer to have more of it. One quiet chip under the last card, centred, wide enough to hit with a thumb and quiet enough that it does not compete with the cards above it.

It is the visible half of a decision the product made about pagination: the feed does not number its pages and it does not load as you scroll. A person asks for more, once, and the screen keeps its scroll position. That is why this is a control and not a sentinel.

Anatomy

Which part is which, in the product's own words. Every class named here is one this file styles, and the build fails if it is not.

The control in it was the category chip drawn in a second file - same --bg-chip ground, same --bevel-notice edge, same 10 corner, same 14px semibold, and a hover and a press that were `.chip-nav`'s byte for byte - so it carries `.chip.chip-nav` and this file carries where it stands. A state belongs to what a person can press or type into, and inventing one here would inflate the system the way an empty semantic role would.

When to use

The judgement a generator cannot read out of css, and the reason ui-kit/authored/loadmore.md exists.

At the foot of a list that has more behind it, and only there. Nine screens: the four categories and the general feed, each logged in and logged out.

It does not belong under a list that is complete, and it does not belong under a list that is empty. Both of those already have their own answers: a complete list simply ends, and an empty one takes a state-block, whose sentence says why there is nothing and whose control offers a way out. Putting a Load more under an empty feed asks a person to fetch more of nothing.

The rule, and the anti-rule

One sentence to follow and one mistake worth naming. An anti-rule has to name the component that should have been used instead, or it is a complaint rather than an address, and the build checks that it does.

Do

One per list, at the foot, and the label names what is being loaded: Load more events, not "Load more".

It wears the category chip and it is not a category. Its ROLE is action - it fetches - and its ATOM is chip, which is the same split the footer's social marks have in the other direction. A role is what a control MEANS; an atom is where its RULES live, and there is exactly one file in this system that says what --bg-chip on --bevel-notice at a 10 corner looks like.

Never

Never use it as the action of an empty screen: nothing is behind it there, and the control that belongs under an empty list is the state-block one, which says what happened before it offers anything.

Seen: wireframes/_critique.md L14, the dead-end finding on the eight category empty screens, where the empty state's own CTA led nowhere. The same screens are the ones this component is deliberately absent from.

How this is read

So the authored half names its sources before it says anything, and the build fails when one of them does not exist.

  • ui-kit/docs/inventory.md L91 - "Load-more control", filed L1, on feed and category, states rest / hover, 20+ screens claimed.
  • The painted screens, counted: 9 carry it, all of them a feed or a category in its full state. It is absent from every empty, error and loading variant, which is the decision this page is mostly about.
  • voice/docs/microcopy.md, where the label is Load more events and not "Show more", "Next" or a page number.
  • components/loadmore.css, whose hover read --bg-control-hover and --line-brass-soft: the graphite chip family's answer, not the button family's. That line was written before the chip family had a file, and it is the whole finding this component was eventually closed by.
  • ui-kit/docs/backlog.md S41, which said on the day it was opened that this control measures as .cat-nav button and that the component should not exist.

/* ============================================================================
   THIS CONTROL IS THE CATEGORY CHIP AND IT ALWAYS WAS, 2026-08-07. Backlog S41
   said so on the day it was opened - "`.load-more` measures, over 105 painted
   screens, as the same graphite chip as `.cat-nav button`" - and named the four
   declarations that were in the way. Three of them were nothing and the fourth
   was an exception with no argument.

     min-height:44px          INERT. The control is 12/24 at 14px, so its content
                              box is 47 before the floor is consulted, at every
                              width and in both themes. It never bound.
     letter-spacing:.01em     the BUTTON family's tracking, which this control
                              wore because it was filed as a button. 0.14px on a
                              14px label.
     padding 12/24            against the chip's 12/20. Four pixels a side.
     box-shadow inset 0 1px 0 a lit top edge, and the only real difference. The
                              chip family decided against one on purpose:
                              components/chip.css carries `box-shadow:none` at
                              rest so that there is nothing lifted to flatten
                              under a finger. One control keeping a groove the
                              other 285 gave up is the same shape as the Trending
                              sub-filter's four pixels of padding, and it is
                              settled the same way: the majority is the face.

   ITS STATES NEEDED NO DECISION AT ALL, which is the strongest evidence the two
   were one control. `.load-more:hover` was `--border-brass-hover` on
   `--bg-control-hover` with `--text-strong`, and `.chip-nav:hover` is those three
   in that order; both press to `--bg-pressed`. Byte for byte, in two files, the
   way `.seg` and `.ed-range` were.

   THE ROLE DOES NOT MOVE AND THE ATOM DOES. Load more is an ACTION - it fetches -
   and `ui-kit/_worn.py` goes on saying so. The atom is where a control's RULES
   live, which is the correction the social mark forced on 2026-08-06: that one is
   `nav` by role and `iconbutton` by atom, and this one is `action` by role and
   `chip` by atom. A role is what a control MEANS and a face is what it IS.

   WHAT IS LEFT IS A ROW, and it is the last thing in this file. `.load-more` is
   kept as a name because the feed's script reaches for it and because a person
   reading the markup should be able to tell the foot of a list from a category
   in a strip.
   ============================================================================ */

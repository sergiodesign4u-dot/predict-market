States

Hover and focus are not faked here with a stand class. The frames above are live, so hover them; what follows is what the file says will move.

No states: not interactive. Declared in ui-kit/_levels.py, and gate 25 holds it: the action bar's own surface, and nothing else since 2026-08-03: a stone, a hairline along the top edge, two rounded corners, and the three declarations .flat takes them away with. The button it used to paint went to button.css where the rest of that family already was (backlog S11), so the bar answers no pointer because a bar is not a control. This entry is the same shape as notice above and for the same reason. A state belongs to what a person can press or type into, and inventing one here would inflate the system the way an empty semantic role would.

What the file says

The selectors and the css, for a person about to edit them. To change this component, edit components/account.css; to change a value it reads, edit the role in components/tokens.css.

components/account.css
/* components/account.css

   Component: account. Classes: .cta-bar, .flat.

   Reads: --bg-card-quiet, --border-hairline
   Stand:  ui-kit/account.html
   Stands on: 3 ui-visual screens (how-it-works.html, my-profile.html, wallet.html)
   Colour goes through a role, geometry straight from a primitive. No em dash. */

/* THE BAR'S OWN SURFACE, and it is the one exception this step declared. The
   arrangement is in components/patterns/action-bar.css; a stone, a hairline
   along the top edge and two rounded top corners are not composition, and
   they are not the page plate either, so they stay with the component that
   draws them. */
.app-case .cta-bar{background:var(--bg-card-quiet);border:0;border-top:1px solid var(--border-hairline);border-radius:var(--radius-10) var(--radius-10) 0 0}
/* THE BUTTON LEFT THIS FILE ON 2026-08-03, and the whole of it: the quiet rest,
   the brass first child, both hovers and both presses, eight rules. They are in
   components/button.css with the rest of the family, because they were the
   family - the same --bg-control, the same 1px --border-hairline, the same
   --text-primary and --radius-10 that .auth-btn, .state-btn and .provider-btn
   each declared separately, plus the one hover the majority already had right.
   That is ui-kit backlog S11: a person assembling an action bar was hitting a
   button rule the button page had never heard of, and the class map could not
   see it either, because the markup here is a bare <button> with no class.
   The arrangement went one step further, to patterns/action-bar.css, which
   already said how an anchor child shares the row.
   What is left is the bar, and only the bar: its stone, the hairline along its
   top edge, its two rounded corners, and the three declarations .flat takes
   them away with. That is the exception this component declared when the
   pattern was cut, and it still holds. */
.app-case .cta-bar.flat{border:0;background:none;border-radius:0}

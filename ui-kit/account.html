Identity, reputation and the profile tabs

What it is

The surface an action bar stands on, and nothing else. Two rules: the bar's own stone with a hairline along its top edge and two rounded top corners, and the variant that takes all three away where the page has no scroll to hold the bar against.

It is a component with almost nothing in it ON PURPOSE, and the emptiness is the record of a decision. The arrangement of an action bar is a composition and went to components/patterns/action-bar.css; the buttons in it are buttons and went to components/button.css; the page plate under it is the frame's and went to components/base.css. What could not go anywhere is the stone, because a pattern may carry no colour and the frame does not know this bar exists. So the exception was declared rather than forced, and this file is the exception.

Anatomy

Which part is which, in the product's own words. Every class named here is one this file styles, and the build fails if it is not.

  • .cta-bar - the bar's surface: --bg-card-quiet, a hairline along the top edge, and two rounded top corners, so a bar sitting at the foot of a scrolling column reads as a shelf the content slides under.
  • .flat - the same bar where the page does not scroll. Border off, background off, corners off: on how-it-works the bar is the end of the page rather than a shelf over it, and a stone there would be a shadow with nothing behind it.

States

Hover and focus are not faked here with a stand class. The frames above are live, so hover them; what follows is what the file says will move.

No states: not interactive. Declared in ui-kit/_levels.py, and gate 25 holds it: the action bar's own surface, and nothing else since 2026-08-03: a stone, a hairline along the top edge, two rounded corners, and the three declarations .flat takes them away with. The button it used to paint went to button.css where the rest of that family already was (backlog S11), so the bar answers no pointer because a bar is not a control. This entry is the same shape as notice above and for the same reason. A state belongs to what a person can press or type into, and inventing one here would inflate the system the way an empty semantic role would.

When to use

The judgement a generator cannot read out of css, and the reason ui-kit/authored/account.md exists.

You do not reach for this file. A person building an action bar takes the action-bar pattern, which says how the row is arranged and where it sticks; the surface arrives with it because components/index.css loads both.

The one decision this component leaves to a person is .flat, and the question is whether the bar has anything to hold itself against. A column that scrolls under it: keep the stone. A page that ends where the bar is: take it away.

The transaction list on the wallet screen is NOT this component, whatever the inventory says. It is position, and the row that claims otherwise is the oldest thing in this file's source list.

The rule, and the anti-rule

One sentence to follow and one mistake worth naming. An anti-rule has to name the component that should have been used instead, or it is a complaint rather than an address, and the build checks that it does.

Do

The bar's material stays here and everything else leaves: an arrangement goes to the pattern, a control goes to its own component, and a page plate goes to the frame.

Never

Never paint the bar's button from this file: a control in an action bar is button, and painting it here gives it a rule the button page has never heard of and a class map that cannot see it, because the markup is a bare element with no class of its own.

Seen: ui-kit/docs/backlog.md S11, which was exactly that for three stages, found by the pattern extraction in step 4 when a bare <button> made the class map unable to see the bar's contents, and closed on 2026-08-03 by moving eight rules out of this file.

What the file says

The selectors and the css, for a person about to edit them. To change this component, edit components/account.css; to change a value it reads, edit the role in components/tokens.css.

/* components/account.css

   Component: account. Classes: .cta-bar, .flat.

   Reads: --bg-card-quiet, --border-hairline
   Stand:  ui-kit/account.html
   Stands on: 3 ui-visual screens (how-it-works.html, my-profile.html, wallet.html)
   Colour goes through a role, geometry straight from a primitive. No em dash. */

/* THE BAR'S OWN SURFACE, and it is the one exception this step declared. The
   arrangement is in components/patterns/action-bar.css; a stone, a hairline
   along the top edge and two rounded top corners are not composition, and
   they are not the page plate either, so they stay with the component that
   draws them. */
.app-case .cta-bar{background:var(--bg-card-quiet);border:0;border-top:1px solid var(--border-hairline);border-radius:var(--radius-10) var(--radius-10) 0 0}
/* THE BUTTON LEFT THIS FILE ON 2026-08-03, and the whole of it: the quiet rest,
   the brass first child, both hovers and both presses, eight rules. They are in
   components/button.css with the rest of the family, because they were the
   family - the same --bg-control, the same 1px --border-hairline, the same
   --text-primary and --radius-10 that .auth-btn, .state-btn and .provider-btn
   each declared separately, plus the one hover the majority already had right.
   That is ui-kit backlog S11: a person assembling an action bar was hitting a
   button rule the button page had never heard of, and the class map could not
   see it either, because the markup here is a bare <button> with no class.
   The arrangement went one step further, to patterns/action-bar.css, which
   already said how an anchor child shares the row.
   What is left is the bar, and only the bar: its stone, the hairline along its
   top edge, its two rounded corners, and the three declarations .flat takes
   them away with. That is the exception this component declared when the
   pattern was cut, and it still holds. */
.app-case .cta-bar.flat{border:0;background:none;border-radius:0}

Six page types asked, three got it

ia/docs/pages/seo.md specifies a trail on six page types and ia/docs/blocks.md files it as block B2, marked MVP. The product rendered zero of them. Three of the six got this component and three did not, and the split is a measurement rather than a preference.

Adding a visible trail to the event detail would have been a FOURTH control made of the same five words. The critique of the same morning had already counted three on the desktop feed: the chip rail navigates, the condensed strip navigates, Show: filters, and nothing distinguishes them. So the visible half of the IA's decision is answered on those two page types by the nav that was already there, and this component goes where nothing answers it.

Anatomy, and three decisions that are not taste

partwhat it iswhy
.crumba <nav aria-label="Breadcrumb"> holding an <ol>ordered, because the order IS the meaning. A landmark, because it is the answer to "where am I" and a reader should be able to jump to it
.crumb ainline-flex, and in base.css's 44px listthe display is the precondition, not the look. min-height does not apply to a non-replaced inline box, so a bare <a> joining that list is silently inert without a box. That file paid for this once already, with .sys-link-list a reading min-height:44px and measuring 39.6 x 21. Measured here: 33 x 44 at 390 with the pointer coarse, 33 x 18 at 1280
the separatorli + li::before, a drawn /never in the accessibility tree and never in a copied line. A / written as a text node reads as part of the next link, and voice/ would have to hold a row for a character nobody wrote

The schema half is not built, and it is not pretended

BreadcrumbList is part of the IA's decision on all six page types and this component emits none. That is not a gap in this file: the product carries 0 application/ld+json of any kind across 108 screens, so breadcrumb schema is one row of a larger absence. docs/backlog.md 171.

The markup is written so the trail survives the day the schema arrives: the list is ordered, the ancestors are in it even when they have no page, and the current item carries aria-current="page" rather than being dropped.

Its sibling is the category nav, and they say different things

The same morning this was written, the category nav was corrected: on an event detail it had marked aria-current="page" on three different links at once, the sticky strip saying Trending, the rail saying Politics and the bottom nav saying Events, none of which is the page the reader is on. 35 of 60 documents had the two category controls naming different categories, and the sticky one, the one on screen while you read, was the wrong one on every event detail and on every logged-out category page.

The value is location now where the link points at an ancestor, and the face does not split: a person reading an event in Politics should see Politics lit, and the distinction between "the page you are on" and "the section you are in" is one an eye does not need and a screen reader does. chip.css carries the argument. This component is the same statement in visible form, on the three page types where no nav makes it.

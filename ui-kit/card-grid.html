Card grid

A fluid track of event cards, one column to four, with no media query at all.

Live

Cut out of event-feed.html byte for byte, with the ancestor chain it has there, and painted by components/index.css alone. Every string is the shipped microcopy, because none of it was retyped. The feed, which is where the track was read from. Trimmed to the first four cards of twelve so the frame stays readable; nothing else is changed, and four is enough to show the track step from one column to two to three.

This is the only place the pattern exists outside the product. A component has a specimen as well as a stand; a pattern has neither, because step 3 took patterns out of gate 24's corpus deliberately: that gate compares what a component contains against what it contains on the screens, and a pattern contains whatever the screen puts in it. So this frame is not an illustration of the pattern, it is the test of it.

Anatomy

What each part is and whose it is. A part that belongs to a component links to that component's page, because the answer to "how does this look" is there and not here: this file decides placement and nothing else.

partwhose it iswhat it does here
.gridthis patternThe track. Three declarations: it is a grid, it stretches its items to equal height, and the columns are computed.
.cardcardWhat stands in it. The card decides nothing about where it stands, and the track decides nothing about what a card looks like.

Everything inside, read from the markup: card (.card), yesno (.yesno), options (.options). The class in brackets is what put each component in the list, through the same ownership map that computes the level and orders the cascade. A name here that surprises you is worth following: a class declared in the wrong file makes a pattern read as holding a component it has never seen.

Variants

No variants. The pattern has one arrangement, and a screen that needs a different one needs a different pattern.

When to use it

  • A screen lists things of one kind and the number of them is decided by the data.
  • The items are the same shape, so a track that reflows beats a layout that is authored per width.

The rule

One grid per screen. It is auto-fit over minmax(min(100%, 300px), 1fr), so the column count is arithmetic on the available width and there is nothing to keep in step with a breakpoint.

The anti-rule

Do not add breakpoints to it. Three of them used to sit beside this rule, stepping 2 - 3 - 4 columns, plus a category variant at auto-fill 240px. All four were dead: they lost to the auto-fit rule on source order, and the variant was only ever held up by an !important that is now gone. A fluid track needs no breakpoints, which is why this file has none.

The file

A pattern loads LAST in components/index.css, after every component, because it has to be able to place what it holds. It carries no colour at all, and gate 23 fails the build if one appears.

components/patterns/card-grid.css
/* components/patterns/card-grid.css
   Pattern: the card grid. A fluid track of event cards, one column to four.

   Assembled from: card. One brick, many of it, which is still a composition:
     what the pattern decides is the track, and the card decides nothing about
     where it stands.
   Stands on: 23 ui-visual screens, exactly the ones that list events
     (event-feed x21 across the four categories and their states, favorites x2).
     Counted from the markup and not by grep: `grid` also matches .grid-l, the
     chart's grid line, on 9 more screens, and .hf-grid on one. Those are not
     this. 23 elements on 23 screens, one grid per screen.
   Moved here from: components/feed.css, three rules, cut and not copied.
   Colour goes through a role, geometry straight from a primitive. No em dash. */

.grid{display:grid}
/* WHAT THE !important WAS ARGUING WITH. Four rules used to sit beside this one:
   three breakpoints stepping the grid 2 - 3 - 4 columns, and a category variant
   at auto-fill 240px. All four were already dead. The three breakpoints lose to
   the auto-fit rule below on source order alone, and the category variant was
   outranked only by the !important that rule carried. So the shipped grid has
   always been the one rule, and the shout was holding a cascade nobody had
   cleaned up. Deleting the four is what made the !important removable without
   moving a card: a fluid auto-fit track needs no breakpoints, which is also why
   this pattern has no media query of its own. */
.grid{align-items:stretch;grid-template-columns:repeat(auto-fit,minmax(min(100%,300px),1fr))}
.grid{gap:var(--space-16)}

How this is read

The component in the markup it ships with, quoted from the frozen kit, inside the product's own wrapper and painted by components/index.css alone. Each frame is a page of its own, so the width under the title is a real viewport and the media queries answer to it. One row per CONTROL, in one column, and a scope is present only where the scope is what the row is about: twelve of the sixteen combinations the product wears were measured against the same markup with no scope above them and came out identical over thirteen properties, so a plate around those would be showing the reader a dialog to prove something about a button. The numbers for every row are in the axis table further down, written once.

What it is

Four amounts a person can take instead of typing one. It stands under the field it fills, in the deposit sheet and in the bet panel, and it is the fastest path through the one screen where speed matters and a typo costs money.

Anatomy

Which part is which, in the product's own words. Every class named here is one this file styles, and the build fails if it is not.

  • .quick - the row. A wrapping flex line, pushed right in a bet panel because the field it fills is right-aligned, and left in a dialog because the label above it is.
  • .quick button - the chip: graphite ground, hairline edge, 10px corner, 12px label.
  • .quick button.sel - the chosen one. A brass TINT, a brass edge and a brass label, and the state is a class rather than a pseudo because the selection survives the pointer leaving.

States

Hover and focus are not faked here with a stand class. The frames above are live, so hover them; what follows is what the file says will move.

No states: not interactive. Declared in ui-kit/_levels.py, and gate 25 holds it: a ROW, and since 2026-08-06 that is the whole of it: a flex line that wraps, and a bet panel pushing it to the right. The amounts went to chip.css as `.chip-amount`, the face a chip wears when it is one of the things you fill in on a sheet, and they took the hover and the press with them. A file holding one layout rule for one row is the shape backlog S41 describes about loadmore, and this file has joined it. A state belongs to what a person can press or type into, and inventing one here would inflate the system the way an empty semantic role would.

When to use

The judgement a generator cannot read out of css, and the reason ui-kit/authored/quick.md exists.

Under a field a person types a number into, when a small set of amounts covers most of what they would type. Two places: the deposit sheet and the bet panel with its sheet.

Not as a way of offering every value. Four chips and a field is a shortcut; twelve chips and a field is a menu that has forgotten it has a field.

The rule, and the anti-rule

One sentence to follow and one mistake worth naming. An anti-rule has to name the component that should have been used instead, or it is a complaint rather than an address, and the build checks that it does.

Do

A selected chip is a tint, never a fill. A solid brass gradient is the primary action's own face, and a deposit sheet had a lit brass $20 sitting directly above a lit brass Add funds until 2026-08-04: the chip was as loud as the commitment. 107 placements moved to --tint-brass-16, which components/tokens.css names, in its own words, "from: a selected quick amount".

Never

Never dress it as a button. It is a selector: it carries a value, and the reason its selected state is visible is that the value stays chosen. A chip lifted out of its row is the half that carries no information, which is the argument ui-kit/authored/button.md makes in its own anti-rule.

And this file is not the merge it looks like. .seg, .ed-range button, .cat-nav button and .load-more are the same graphite chip drawn in four other files, and giving one of them a file of its own does not consolidate them. What it does is make the shape of the merge visible: four files, one control, and the same measurement that ended five button names is what would end these.

Seen: ui-kit/docs/backlog.md S41, and ui-kit/docs/defects.md row 63, which is the pass that found this file had been filed as part of an atom.

How this is read

So the authored half names its sources before it says anything, and the build fails when one of them does not exist.

  • components/input.css, where these chips lived until 2026-08-05. A field and a group of chips are not one thing: input is a label, a field and the row that holds them, and this is a ROW OF CHIPS a person chooses between.
  • ui-kit/_worn.py, which had already filed them under a different ROLE from everything else in that file: a quick amount is a selector, and a field is not. 480 placements over 105 screens.
  • ui-kit/docs/defects.md row 63 and ui-kit/docs/backlog.md S41 - the pass that split them. input had an EMPTY containment, so ui-kit/_levels.py called it an atom with nothing to go on.
  • DESIGN.md, twice: "active is a brass tint" under Chips, and the One-Accent Rule. Both decide the selected state below.
  • ui-kit/docs/backlog.md S38, which owns the gap this control shares with every other selected chip in the product.

What the file says

The selectors and the css, for a person about to edit them. To change this component, edit components/quick.css; to change a value it reads, edit the role in components/tokens.css.

   IT LEFT components/input.css ON 2026-08-05, BECAUSE A FIELD AND A GROUP OF
   CHIPS ARE NOT ONE THING. `input` is a label, a field and the row that holds
   them, which is an atom; this is a ROW OF CHIPS a person chooses between, which
   is a molecule, and the census in `ui-kit/_worn.py` had already filed the chips

   selectors, and a field is not.

   Gate 39 is what surfaced it. `input` had an empty containment, so `_levels.py`

   is kept for the reason the rest of the system keeps its first layer: the
   painted rules below are all scoped, and an unscoped element still has to be a
   chip rather than a browser button. */
/* THE AMOUNTS LEFT THIS FILE ON 2026-08-06 for components/chip.css, where they are
   `.chip.chip-amount`: --bg-control on a hairline inside a 10 corner, which is the face a
   chip wears when it is one of the things you fill in on a sheet. The deposit dialog's copy
   and the bet panel's measured identical at rest and are one face; what had separated them
   was the CHOSEN state, and S35 settled that the day before.
   WHAT IS LEFT IN THIS FILE IS A ROW, and that is now the whole of it: a flex line that
   wraps, and a bet panel pushing it to the right. A file holding one layout rule for one
   row is the shape ui-kit/docs/backlog.md S41 describes about loadmore, and this file has
   just joined that row.
   ONE THING WAS DECIDED RATHER THAN CARRIED, and it lives entirely inside :hover, so no
   before-and-after in this repo can see it. The deposit sheet's amounts answered a
   pointer - a brass edge, a brass label, --bg-control-hover - and the bet panel's, the
   same face on the same control, answered nothing at all. One scope having a hover and
   the other not is not a decision anybody took, so the face takes the hover and both
   scopes now answer. It stays `:not(.sel)`, and on 2026-08-07 that became a decision
   instead of a gap: no chosen control in this product answers a pointer, all six
   measured, because a chosen face is already the answer. The FINGER was the real gap
   and S38 closed it - every chip presses to --bg-pressed now, chosen or not. The state
   gallery is what checks this, because it photographs all four faces and a snapshot
   photographs one. */
.quick{display:flex;gap:var(--space-8);flex-wrap:wrap}

dialog.app-dialog .quick{display:flex;gap:var(--space-8);flex-wrap:wrap}
/* A SELECTED CHIP IS A TINT, AND A SOLID BRASS FILL IS THE PRIMARY ACTION'S OWN
   FACE. This rule painted the chosen quick amount as a full brass gradient on 107
   placements, and DESIGN.md decides it twice over: "active is a brass tint
   (rgba(199,162,78,.08) fill)" under Chips, and the One-Accent Rule, "brass
   carries identity, the active state, and primary CTAs only ... if a screen has
   brass on more than the logo, the active chip, and the primary action, it is
   overspent". A deposit sheet had a lit brass $20 sitting directly above a lit
   brass Add funds, and the chip was as loud as the commitment.
   THE PRODUCT ALREADY HELD THE ANSWER IN TWO PLACES. The same class in the bet
   panel and the bet sheet is `--tint-brass-16` (line below in this file), and
   tokens.css names that token, in its own words, "from: a selected quick amount".
   The token was cut from this control and this control disagreed with it. 107
   placements move to the tint, 11 already wear it, and the chip family loses the
   one member that was shouting.
   THE HOVER AND THE PRESS GO WITH THE GRADIENT, and that is a consequence rather
   than a decision: they were the three-step of a brass PLATE, and there is no
   plate now. What is left is what every other selected chip in this product does,
   which is nothing, on `.seg`, on `.ed-range` and on the panel's own quick row.
   That gap is real and it is uniform; `ui-kit/docs/backlog.md` S38 owns it rather
   than this file inventing a fourth answer.
   AND S38 ANSWERED THE PRESS ON 2026-08-07, in components/chip.css and in one
   selector: every chip settles onto --bg-pressed under a finger, chosen or not,
   keeping its brass edge, its brass label and its halo. Not a fourth answer - the
   FIRST one, the quiet control's, which the `[aria-current]` chips already had. */
/* AND ONE MORE STEP OF THE SAME WALK, 2026-08-06. The paragraph above took this control off a
